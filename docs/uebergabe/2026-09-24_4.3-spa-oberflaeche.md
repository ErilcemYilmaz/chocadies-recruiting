# Uebergabe: 4.3 SPA Web-App, Oberflaeche nach Wireframe

Datum: 2026-09-24 · Commits: vier Commits vom 24.09. (chore/feat/test(web), docs), siehe `git log -- web`

## Umgesetzt

Hinweis vorab: Der Auftrag nannte dies "Teil 2". Ein Teil 1 (Grundgeruest
der SPA) war im Repository nicht vorhanden, `web/` enthielt nur eine README.
Das Grundgeruest (Vite, React, TypeScript, Routing, API-Client, Tests) ist
deshalb in diesem Block mit entstanden.

- **Grundgeruest** `web/`: React 19, Vite 8, TypeScript 5.9, React Router 7,
  Vitest 5 mit Testing Library und jsdom. Der Vite-Server leitet `/v1` an
  die Server-App auf Port 3000 weiter (kein CORS noetig).
- **Screens** (`web/src/seiten/`):

  | Wireframe | Datei | Route |
  |---|---|---|
  | S1 Anmeldung | `Anmeldung.tsx` | `/anmeldung` |
  | S2 Bewerbungen (+ mobil) | `Bewerbungsliste.tsx` | `/bewerbungen` |
  | S3 Bewerbungsdetail | `Bewerbungsdetail.tsx` | `/bewerbungen/:id` |
  | S4 Neue Bewerbung | `NeueBewerbung.tsx` | `/bewerbungen/neu` |
  | S5 Bewerbung bearbeiten | `BewerbungBearbeiten.tsx` | `/bewerbungen/:id/bearbeiten` |
  | S6 Loeschen bestaetigen | `komponenten/Bestaetigungsdialog.tsx` auf S3 | – |

- **Wiederverwendbare Komponenten** (`web/src/komponenten/`): `Seitenleiste`
  (Marke, Navigation, Person, DE/FR, Abmelden), `Layout` (Seitenleiste oder
  mobile Kopfzeile mit Hamburger-Menue und "+"), `Bestaetigungsdialog`,
  `Feld` (Label, Pflichtstern, Fehler- und Hinweistext), `Meldung`,
  `StatusBadge`, `formular/BewerbungFormular` (gemeinsam fuer S4 und S5),
  `formular/DokumentAuswahl`.
- **Gestaltung:** eigenes CSS ohne UI-Bibliothek. `web/src/styles/variablen.css`
  definiert Akzentfarbe `#4A2C1D`, Schrift Inter (selbst gehostet ueber
  `@fontsource-variable/inter`), Abstaende im 8-px-Raster (`--r-1` = 8 px bis
  `--r-6` = 48 px, dazu 4 px und 12 px als Halbschritte). `app.css` verwendet
  nur diese Variablen.
- **Responsiv unter 768 px** (S2 mobil): Kopfzeile mit Hamburger-Menue (die
  Seitenleiste oeffnet als Schublade), Titel und rundem "+". Filter hinter der
  Schaltflaeche "Filter" mit Zaehler der aktiven Filter, Tabelle als Karten
  mit "Details anzeigen →". Formulare und Detailkarten einspaltig.
- **Sprachumschaltung DE/FR:** `web/src/i18n/uebersetzungen.ts` enthaelt alle
  sichtbaren Texte. Die franzoesische Fassung ist als `typeof de` typisiert,
  ein fehlender Text bricht den Build ab. Die Sprache wird im Browser gemerkt
  und als `lang`-Attribut gesetzt. Datumsformat `de-CH` bzw. `fr-CH`.
- **Anzeigenamen der Enums** zentral in `web/src/i18n/anzeigenamen.ts`
  (Status, Standort, Dokumenttyp, Quelle, Sprache), typisiert gegen die
  Wertelisten in `web/src/api/typen.ts` (1:1 aus `api/openapi.yaml`).
- **API-Anbindung:** `web/src/api/client.ts` ist die einzige Stelle mit
  `fetch` und Bearer-Token. Fehler kommen als `ApiFehler` (Status, Code,
  Details) zurueck, 401 fuehrt zur Anmeldung ("Sitzung abgelaufen"), 409 zur
  Warnung aus S4, 400 zu Fehlern beim Feld.
- **Barrierefreiheit:**
  - Jedes Feld hat ein sichtbares `<label>`. Der Pflichtstern ist
    `aria-hidden`, die Pflicht meldet `aria-required`.
  - Fehler stehen als Text direkt beim Feld und sind per `aria-describedby`
    verbunden, dazu `aria-invalid`. Beim Speichern springt der Fokus auf das
    erste fehlerhafte Feld.
  - Sichtbarer Fokusrahmen ueberall (`:focus-visible`), auf der dunklen
    Seitenleiste in Gelb.
  - Loeschdialog als `role="alertdialog"` mit `aria-modal`, Titel und Text
    verknuepft. Fokus startet auf "Abbrechen", Tab bleibt im Dialog, Escape
    bricht ab, danach kehrt der Fokus auf "Loeschen" zurueck.
  - Meldungen: Warnung/Fehler als `role="alert"`, Erfolg als `role="status"`.
  - Sichtbarer Text ist immer Teil des zugaenglichen Namens (WCAG 2.5.3),
    z.B. "DE, Deutsch" oder "Filter (2 Filter aktiv)".
  - Kontraste: Fliesstext grau `#4B5563` auf Weiss 7.6:1, Platzhalter
    `#6B7280` 4.8:1.

## Entscheidungen und Alternativen

| Entscheidung | Verworfene Alternative | Begruendung (Stichworte) | Passende Quelle aus APDE_Entscheidungen_und_Setup.md |
|---|---|---|---|
| Eigenes CSS mit CSS-Variablen | UI-Bibliothek (MUI, Bootstrap) | Vorgabe; Wireframe-Treue; keine fremde Designsprache; kleiner Bundle | Material Design 3 / Apple HIG nur als Referenz fuer mobile Muster |
| Uebersetzung als typisiertes TS-Objekt mit React Context | i18next | zwei Sprachen, wenige Texte; Build bricht bei fehlender Uebersetzung ab; keine Abhaengigkeit | – (Projektentscheidung) |
| Enum-Anzeigenamen getrennt von den Texten, typisiert gegen die API-Werte | Werte direkt anzeigen / in jeder Seite uebersetzen | eine Stelle; neuer Enum-Wert in der Spezifikation erzwingt Anpassung | OpenAPI Specification v3.1.1 |
| Vite-Proxy fuer `/v1` | CORS-Header in der Server-App | Server bleibt unveraendert; produktiv gleicher Ursprung hinter Reverse Proxy | OWASP API Security Top 10 (API8 Security Misconfiguration) |
| Schrift selbst gehostet (`@fontsource`) | Google Fonts CDN | keine Uebertragung der IP-Adresse an Dritte beim Seitenaufruf | DSG SR 235.1; DSGVO |
| Eigener Dialog mit Fokusfalle | natives `<dialog>` mit `showModal()` | jsdom (Tests) kennt `showModal` nicht; Verhalten explizit testbar | WCAG 2.2 (2.1.2 Keine Tastaturfalle, 2.4.3 Fokusreihenfolge) |
| Fokus im Loeschdialog auf "Abbrechen" | Fokus auf "Endgueltig loeschen" | endgueltige Aktion, sichere Wahl zuerst | Nielsen (1994), Heuristik 5 Fehlervermeidung |
| Filter und Seite in der URL | nur im Komponentenzustand | "Zurueck" aus dem Detail zeigt dieselbe Liste; Link teilbar | Nielsen (1994), Heuristik 3 Nutzerkontrolle |
| Clientpruefung spiegelt die API-Constraints | nur Serverpruefung | Fehler sofort beim Feld; Server bleibt massgeblich | WCAG 2.2 (3.3.1 Fehlererkennung, 3.3.3 Fehlerempfehlung) |

Hinweis zu Quellen: Die WAI-ARIA Authoring Practices (W3C) fuer das Muster
"Alert Dialog" sind im Code erwaehnt, stehen aber nicht in der Quellenliste.
Wird das in der Arbeit zitiert, muss die Quelle ergaenzt werden.

## Abweichungen vom Wireframe

Alle Abweichungen entstehen, weil die API etwas nicht liefert, oder sind
kleine Ergaenzungen ohne Gegenstueck im Wireframe.

| Screen | Wireframe | Umsetzung | Grund |
|---|---|---|---|
| S1 | Anmeldung mit E-Mail und Passwort | Maske identisch, Pruefung gegen ein Demo-Konto aus `web/.env.local`, danach Test-Token aus `npm run token:intern` | API stellt keine Tokens aus (bearerAuth: vorgelagerter Anmeldedienst). Prototyp-Loesung, Werte stehen im Browser-Bundle |
| S1 | – | Zusaetzlicher Hinweis "Ihre Sitzung ist abgelaufen" nach 401 | Token ist 8 h gueltig |

Links in S3 fuehren deshalb noch ins Leere |

## Nachweise

Ausgefuehrt am 2026-09-24 lokal unter Windows 11, Node 22.15:

| Befehl | Ergebnis |
|---|---|
| `cd web && npm test` | 3 Testdateien, 12/12 Tests bestanden |
| `cd web && npm run build` (tsc + vite build) | fehlerfrei |
| `cd server && npm test` | 20/20 Tests bestanden (unveraendert) |
| `cd server && npm run test:newman` | bestanden (unveraendert) |
| `cd server && npm run build` | fehlerfrei |

Web-Tests im Detail:
- `tests/loeschdialog.test.tsx` (6): Dialog oeffnet modal mit Namen und
  Fokus auf "Abbrechen"; Escape schliesst ohne Loeschen und gibt den Fokus an
  "Loeschen" zurueck; "Abbrechen" loescht nicht; Tab/Shift+Tab bleiben im
  Dialog; Loeschen per Tastatur ruft die API und fuehrt mit Meldung zur
  Uebersicht; bei Fehler bleibt der Dialog offen und zeigt ihn an.
- `tests/sprache.test.tsx` (4): Umschalten auf der Anmeldung (Texte,
  `aria-pressed`, `lang`, Speicherung); gespeicherte Sprache wirkt auf
  Tabelle, Enum-Werte und Seitenleiste, Zurueckschalten ohne neue
  API-Anfrage; jeder Text existiert in beiden Sprachen; jeder Enum-Wert hat
  zwei Anzeigenamen.
- `tests/formular.test.tsx` (2): Fehler beim Feld mit `aria-describedby`
  und Fokus auf das erste fehlerhafte Feld; 409 zeigt die Warnung, leere
  optionale Felder gehen nicht an die API.
